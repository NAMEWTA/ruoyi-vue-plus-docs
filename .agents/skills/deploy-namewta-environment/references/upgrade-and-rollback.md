# 升级与回滚

## 升级

1. 分配不可变 Release ID，并记录源码修订。
2. 读取上一份报告、活动清单和 Schema 状态。
3. 分类应用、配置、Schema、OSS 策略、Nacos 与前端路由变化。
4. 备份配置、数据库、对象存储元数据与当前版本，并验证备份可读。
5. 构建、传输并校验新版本到暂存目录。
6. 只执行评审过的向前迁移，优先使用 expand-and-contract。
7. 逐个滚动后端实例，再发布前端与入口。
8. 运行完整验证并观察约定时长的日志和指标。
9. 提升版本并生成新报告，包含精确回滚命令。

## 回滚

1. 指定目标版本，并证明其清单与配置兼容。
2. 停止继续提升，保留失败日志/状态并通知运维责任人。
3. Schema 向后兼容时先回滚应用和配置。
4. 只有明确授权且存在验证过的时间点备份时，才恢复数据库或对象数据。
5. 逐个重启后端，再恢复前端。
6. 重跑全部门禁并生成回滚报告。

禁止 `docker compose down -v`。根因证据保存前不得删除失败版本。签名 OSS、登录、Nacos 一致性或入口仍失败时，不得宣称回滚成功。
