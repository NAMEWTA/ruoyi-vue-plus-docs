# 品牌迁移合同与验收

本参考用于全量迁移中的产品品牌替换。目标不是机械字符串替换，而是让迁移后的当前产品面只表达用户确认的新品牌，同时保留必要的第三方坐标、法律归属和不可变历史。

## 1. 冻结品牌合同

在创建 staging 前向用户展示并确认下表。仓库能证明的事实先读取；用户未提供的品牌身份、资产和公开地址不得猜测。

| 字段 | 必填规则 |
|---|---|
| 显示名称 | 必填；用于完整产品名、README 和应用标题 |
| 产品短标识 | 必填；用于紧凑 Logo、favicon 备用内容和空间受限界面 |
| 主 Logo | 提供可访问的 SVG/PNG 文件路径，或明确批准生成/临时文字标策略 |
| 紧凑 Logo | 明确提供、从主 Logo 合规派生，或批准复用主 Logo |
| favicon | 明确提供、从品牌资产合规派生，或批准使用产品短标识 |
| 深浅色变体 | 明确提供或确认同一资产在两种背景均可用 |
| 法律主体 | 版权主体、package 作者和 SpringDoc 联系人；可为空但不能沿用旧作者 |
| 版权文案 | 明确文案或明确不显示 |
| 产品文案 | 登录/注册标题、简短说明、首页定位；可由显示名称推导后交用户确认 |
| 公开地址 | 官网、文档、支持、公开仓库逐项记录；缺失时删除旧入口，不创建占位链接 |
| 上游可见性 | 默认“隐藏”；仅法律、迁移和同步文档保留旧基座来源 |
| 社交登录平台 | 明确保留的平台；未获确认的旧代码托管平台登录入口默认移除 |
| 运行命名空间策略 | 明确提交模板中的数据库、bucket、容器、网络、服务账号名是重命名还是保留 |
| 真实中间件策略 | 默认“保留”；真实地址、账号、密码和未跟踪运行状态不因品牌替换而改写 |

任一必填项未决时停止写入。资产文件存在不等于用户已授权其作为产品 Logo；记录来源和授权范围。

## 2. 建立旧品牌清单

从源码和实际运行面提取待退役 token，不只搜索 `RuoYi`。至少包括：

- 大小写、连字符、下划线和中英文品牌变体；
- 上游作者、团队、邮箱、版权文案；
- GitHub、Gitee、文档站、演示站、博客和赞助链接；
- 旧 Logo、favicon、图片 hash、组件名、icon 名和自动导入声明；
- Java package、Maven artifact、pnpm scope、应用类和目录名；
- 数据库、bucket、容器、网络、MQTT client/user 等提交默认命名；
- 菜单外链、社会化登录 source、默认管理员昵称和系统配置数据；
- Banner、SpringDoc/OpenAPI metadata、package author/repository、邮件模板和错误页。

为每个命中分类：

1. `project-owned-current`：当前产品代码、配置、数据或文档，必须迁移；
2. `third-party-coordinate`：依赖 group/import/package，必须保留；
3. `legal-provenance`：LICENSE、NOTICE、专用上游/迁移文档，可保留但不得成为产品入口；
4. `immutable-history`：不可变 OpenAPI revision 与已发布 Git Tag 保持不变；当前 SQL 基座直接修改，存量库升级通过 Tag 差异生成临时迁移；
5. `live-runtime-state`：未跟踪私有配置或真实环境值，按用户确认策略处理；
6. `generated-output`：从已修改源重新生成，不手工编辑。

不得保留未分类命中，不得用整目录排除掩盖当前产品残留。

## 3. 按产品面迁移

### 前端与视觉资产

- 替换主 Logo、侧栏/导航紧凑 Logo、favicon、登录/注册视觉和 PWA manifest 图标。
- 更新 document title、meta、登录/注册文案、首页、错误页、空状态、版权和 i18n。
- 删除旧仓库、文档、演示、赞助按钮及其组件、SVG、自动导入声明和翻译键。
- 社交登录只保留品牌合同允许的平台；列表展示采用允许平台白名单，避免升级前旧数据重新出现。
- 校验 SVG `viewBox`、PNG 尺寸/透明背景、深浅色对比和响应式布局；资源请求必须为 2xx 且非空白。

### 后端与运行元数据

- 更新所有应用 Banner、SpringDoc title/description/contact、Actuator/监控显示名和项目自有应用描述。
- 移除已退役社交平台的配置与项目自有 provider 分支；不要删除第三方库中未被项目暴露的实现。
- 更新项目自有默认账号展示名、邮件发件显示名、通知模板和可见错误/欢迎文案。
- 检查 profile、扩展应用和测试 fixture，不能只修改主 Admin 配置。

### 数据与升级路径

- fresh baseline 直接呈现新品牌；已安装环境必须有幂等升级路径。
- 直接更新 `release-artifacts/docker/infrastructure/mysql/init/50-namewta-ddl.sql` 与 `60-namewta-dml.sql` 的当前完整基座，并更新/删除旧菜单外链、管理员昵称、社会化关系和产品自有资源配置。
- 不修改历史块来制造字符串归零；用新迁移建立当前状态，并在残留 guard 中将历史范围精确列为 immutable。
- 不执行真实数据库迁移，除非用户另行授权；交接时明确给出需要应用的迁移标识。

### 发布、配置与文档

- 更新 Docker/Compose 的服务、容器、网络、数据库、bucket 和示例账号名时，遵守“运行命名空间策略”。
- 未跟踪本机配置、真实私有地址和秘密时，遵守“真实中间件策略”；不得把秘密写入提交文件或报告。
- 根 README、文档导航、包元数据和帮助入口以新品牌为当前产品身份。
- 上游来源只放在 LICENSE/NOTICE、迁移映射或专用同步文档；默认用户路径不出现旧基座宣传入口。
- OpenAPI metadata 变化时按仓库生成合同创建新 revision 并更新 current pointer，不改写不可变历史。

## 4. 建立品牌残留 guard

在迁移后的仓库创建项目自有、非写入式校验脚本，并纳入根级质量命令。脚本至少：

- 扫描当前前端 App、后端资源/源码、发布资产、默认 README 和脚本；
- 检查旧名称、作者、邮箱、上游产品 URL、已退役资源路径；
- 断言新 Logo/favicon 存在，旧资源和旧入口组件不存在；
- 检查当前完整基座包含必要的菜单、用户和社会化关系处理，并为已有环境提供源/目标 Tag 差异方案；
- 排除依赖缓存、构建目录和精确的 immutable/legal allowlist；
- 对每个 allowlist 条目记录路径、分类和原因，禁止宽泛 `docs/**` 或 `sql/**` 排除。

同时在生产构建后扫描 `dist`。第三方 CSS/JS 可能包含未使用的 provider/icon 类名；只有证明它来自第三方打包内容且不会渲染或形成链接时才允许保留，并记录证据。

## 5. 浏览器验收

使用 Playwright 覆盖至少一个匿名流程和一个登录后流程：

- title、favicon、Logo 和产品名为新品牌；
- 登录、注册、首页、导航、个人中心不显示旧品牌；
- 不存在旧 GitHub/Gitee/文档/演示入口或已退役社交登录；
- 新品牌公开链接与合同完全一致，不使用占位 URL；
- 桌面与移动 viewport 无文字溢出、遮挡、破图和空白资产；
- 记录桌面与移动截图，并检查浏览器 console 和失败资源请求。

API 可用性与品牌验收分开报告。使用 mock API 的 E2E 可以证明 UI 合同，但不能冒充真实后端集成通过；使用未启动后端的静态预览时，明确标注接口错误属于环境限制。

## 6. 完成条件

只有同时满足以下条件才报告品牌迁移完成：

- 用户已确认品牌合同和最终资产；
- 当前产品源码、配置、种子/升级数据、文档和生产构建只展示新品牌；
- 旧产品链接、作者、Logo、favicon、社交入口和宣传内容已移除；
- 所有剩余旧 token 均有精确分类和保留证据；
- brand guard、前后端门禁、Playwright 和截图审查均已通过；
- 真实数据库、外部服务或 OpenAPI 刷新未执行时，交接中明确列为待部署动作，而不是宣称已完成。
