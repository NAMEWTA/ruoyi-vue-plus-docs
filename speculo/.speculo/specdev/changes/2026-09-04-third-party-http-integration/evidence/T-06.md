## Implementation

DB remains the fact source. `ThirdConfigCacheAdapter` stores provider/endpoint snapshots in the `third:config:` Redis namespace behind `ThirdConfigSnapshotPort`. It registers a handler with the existing `ClusterCacheInvalidationCoordinator`, remembers only hashed local key fingerprints, evicts exact endpoint keys after endpoint/credential writes, and clears the provider namespace after provider writes; each successful write sends an acknowledged invalidation to every subscribed node. Gateway runtime validation rechecks snapshot schema before use. Redis or snapshot uncertainty returns `CONFIG_UNAVAILABLE` and never uses an unknown stale snapshot.
